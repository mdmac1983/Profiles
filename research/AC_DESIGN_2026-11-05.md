## 2. WHAT TO BUILD (v0.7.3). Order = value / risk. Every rule is a pure class with JVM tests first.
### A. Solitaire switch is the ONE switch for automatic opening (AC2, AC8)  [small, safe]
- `ReturnReset.autoOpenWanted(c)` = `Features.get(c, TjHooks.STARTUP_KEY, true)`. Gate: `startTargetBehindLock` (return, start nothing), `openApp` (switch off = the existing "no app" branch: hide cover + `goHome()`), keep `TjHooks` as is.
- Control: rename the toggle "Open Solitaire automatically", subtitle says what OFF means (never after boot, behind the lock screen or after a return from Quickstep).
- Emulator: with the switch OFF, lock + wake: no Solitaire task is created (`dumpsys activity recents` has no Solitaire), custom home in front behind the lock.

### B. Lock-screen rules that do not depend on a wiped switch (AC1, AC7, AC8, AC9)  [core, needs care]
Core rules become UNCONDITIONAL (only a tripped breaker or "Restore everything" pause them):
1. **Plain unlock ends a Quickstep session** (`plainUnlockEndsQuickstep` no longer reads `profile_end_on_lock`; the toggle disappears from Control).
2. **Custom home is prepared behind the lock on every locked wake** (home only; Solitaire only if rule A allows). The `profile_prearm` toggle stays as an explicit OFF-ramp ("Prepare the custom launcher behind the lock screen"), default ON.
3. **A handshake puts the stock home in front behind the lock immediately, whatever `profile_prearm` says**, and the unlock verifies it (re-start up to 2 times at +0.6 s / +1.5 s if the foreground is not the stock home).
4. **The pad latch survives a wrong PIN**: a plain Enter within `RETRY_GRACE_MS` (20 s) of an armed pad latch keeps it (refreshing it); `VALID_PAD_MS` 8 s -> 20 s.
5. "Restore everything" must still mean nothing switches for you: add `CrashGuard` "paused" (set by the Restore button, cleared by every deliberate way back to custom, same as `clearTripped`); `wasTripped` stays the breaker's, a new `automationPaused(c)` = tripped || paused is what these rules read.
6. **Decision log** (`LockLog`, ring file in `filesDir`, <= 64 KB): every screen on/off, pad shown/hidden, key CLASS only (never the digit), the leading 2 pad classes at Enter, handshake armed/withdrawn, USER_PRESENT decision with mode before/after, Enter-to-USER_PRESENT ms, router starts, service connect/disconnect. Added to the tablet report and the last lines shown in Control. This is how the next "it opened Quickstep" gets an answer instead of a hypothesis.
7. (second priority) reconcile after a late bind: at `onServiceConnected` (and at a non-pre-arm Home press) in Quickstep mode, ask `UsageStatsManager` (GET_USAGE_STATS is granted) whether the keyguard was shown since the session began (`KEYGUARD_SHOWN`/`KEYGUARD_HIDDEN`/`SCREEN_NON_INTERACTIVE` events) and no handshake was confirmed -> end the session. Covers "the service was dead at unlock".
- Emulator (section `u`/`x`/`e1` already drive the PIN pad): plain PIN after a Quickstep session with `profile_end_on_lock` explicitly false -> custom; handshake with `profile_prearm` false -> Quickstep in front BEFORE the unlock; wrong PIN after the gesture then the right PIN -> Quickstep.

### C. Battery saver guard (AC3)  [new, contained]
- `BatterySaverGuard` + pure `BatterySaverPolicy` (JVM tests). Setting: `Settings.Global "low_power"` (and `low_power_sticky`); WRITE_SECURE_SETTINGS is already granted. In Android 10 `BatterySaverStateMachine.setSettingsLocked` reacts to a change of `low_power` by enabling/disabling battery saver, so writing 0 turns it off (FACT from AOSP, confirmed by the emulator test below).
- "Prepared ahead of time": a `ContentObserver` on `low_power` registered in `TjApplication` (process-wide, zero polling): when it turns 1 while the mode is CUSTOM (and the switch is on) the observer writes 0 at once on the same thread; `Mode.set(CUSTOM)` also checks once (this is what fixes "turned on in Quickstep, then went to custom"). Rate limit like the radios guard (max 4 writes / 60 s) so a ROM that insists cannot make a loop.
- Switch in Control ("Turn battery saver off in the custom launcher", default ON, Tj asked for it); Quickstep is never touched; nothing is restored on return (offer later: "put it back when I return to Quickstep").
- Emulator: custom mode + `settings put global low_power 1` -> `low_power` is 0 within 3 s and the log line `BATSAVER off` exists; Quickstep mode: stays 1.

### D. Power-menu overlay on the lock screen (AC6)  [needs the tablet's numbers; do the part that does not]
1. V5 dim: draw the patch with the stock dialog scrim factor (default from the emulator measurement, nudge "Patch dimming %" in Control) so it matches the dimmed screen around the open menu.
2. The wallpaper MODEL gets the keyguard dim (default 0.755 measured on the emulator) so the model patch is not a bright rectangle; stored calibration (`lock_cal`) already persists scale/shift per wallpaper+rotation.
3. Card geometry from the PANEL, not from one text node: card = panel top .. panel bottom minus one item pitch, where pitch = (Screenshot item top - Power-off item top) / 2 when both are found.
4. **Cable-free measurement**: when the stock menu is seen on the lock screen / home the service stores a compact dump of its node tree (class, view id, text, bounds, clickable) and the numbers it used (rect, item top/height, pitch, rotation, density, font scale, patch status, calibration, helper reachable) in `power_menu_dump_lock` / `_home`; `ReportState` prints them; the summary shares them. Tj sends the report; Claude reads exact geometry.
5. "Permanent overlay, stock menu never visible": **not shippable blind**. A permanent opaque patch is invisible only if it is pixel-exact; if it is off by a few pixels or a few % brightness it is a visible rectangle on the lock screen ALL the time. Plan: build it behind a switch (default OFF) that keeps the patch at alpha 1 whenever the lock screen shows no notification/PIN pad in that region, switched on only after one cable-time measurement (screenshots of the lock screen with the menu closed and open, `research/ADB_LOCKMENU_PROBE.md`) proves the patch matches (MAE small). Tell Tj plainly.
