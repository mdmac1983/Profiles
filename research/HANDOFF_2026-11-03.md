## How the product works (current behavior, v0.3.1)
- Default Home = our router. **CUSTOM mode** = ported Launcher3 (5 cols x 8 rows, no dock, no "^" caret, 50% white drawer scrim). **QUICKSTEP mode** = router forwards Home to the stock launcher.
- Two-finger **clockwise twist** (in the custom launcher) -> Quickstep. **Double-press Home within 0.9 s** (in Quickstep) -> back to custom AND the return reset (kill bg apps, Wi-Fi + Bluetooth off, optional accessibility "Clear all" in the notification shade (B1) and Recents (B2), then Solitaire started LAST and re-started until verified in front). Also Solitaire opens when the launcher process starts (boot/restart).
- Launcher control (app icon, only visible/openable in Quickstep mode): choose shown apps, power-menu mode, A/B1/B2/keyboard/startup switches, "Last reset" report, Restore everything. Hidden/never-allowed apps are invisible in the custom drawer and its search; apps installed later start hidden.
- Power menu: accessibility helper (Settings > Accessibility > "Launcher power-menu helper") covers the whole system card with a Power off + Restart card (Screenshot gone), custom mode only, never on the lock screen, fail-open.
- Method A (default ON): apps launched from the custom launcher get FLAG_ACTIVITY_EXCLUDE_FROM_RECENTS except the target app (label "solitaire"); our own screens are excluded too.
- Keyboard switch needs ONE adb command (`adb shell pm grant com.tj.launcher android.permission.WRITE_SECURE_SETTINGS`), default OFF.
- The reset/hide/Recents settings live in prefs files `tj_mode`, `tj_features`, `tj_apps`, `tj_kb` (the emulator scenario writes them with `run-as`).

## How to work (commands)
- Session start: `bash tools/install-hooks.sh` (hooks are not loaded from the repo when it sits under /home/user). `bash tools/resume.sh` prints the briefing.
- Build/test locally (ONE Gradle at a time): `bash tools/gradle.sh :app:testDebugUnitTest :app:assembleDebug --console=plain > /tmp/x.log 2>&1` (~1-2 min; never run `./gradlew` directly; release builds are refused locally without the keystore, by design).

- **Emulator proof (the safety gate):** `emulator.yml` (manual dispatch on branch `ccr-4ff66321-chzhhg`; ~9 min) runs `tools/emulator_scenario.sh` on an Android 10 emulator at 600x1024/170 dpi/font 1.2: router, mode flips, crash breaker, uninstall fallback, hide apps, search, reinstall=hidden, lock, reset, Recents policy, startup open, power-menu card + real Restart press. Download the artifact (`list_workflow_run_artifacts` -> `download_workflow_run_artifact` -> curl the URL -> unzip with `python3 -I`), read `results.txt` (PASS/FAIL/INFO), screenshots, logs. The emulator has a non-Quickstep launcher, so it cannot test Quickstep Recents or two-finger touches.
- **Ship:** bump versionCode/versionName in `app/build.gradle.kts`, write notes in `research/FIRST_INSTALL.md` + tick TASKS, `bash ship.sh "note"` (local gates), then dispatch `android.yml` on `main` with `full_build=true`, confirm `get_release_by_tag`, then `bash tools/record-release.sh vX.Y.Z "note"`, give Tj the Release link as plain text. MIRROR_MAIN=on: every push also fast-forwards `main`.
- A brand-new workflow with only tag/dispatch triggers is invisible to the API until one event touches it (add a temporary path-filtered `push:` trigger, push, remove it) — see CLAUDE.md.
- Be careful with big tool outputs (`get_job_logs` without `tail_lines` floods the context); monitors: use `Monitor` with a `sleep`, never poll; a stale "monitor completed" notification can arrive for an older run — check the actual run id.

## Lessons / traps learned the hard way
- An accessibility `findAccessibilityNodeInfosByText` also finds OUR OWN overlay (self-click loop): always skip windows of our own package; press buttons only inside systemui/launcher3 windows.
- `am force-stop` unbinds the accessibility service: re-enable it in tests (`rebind`); forcing a mode change by editing prefs does not run `Mode.set` (so no keyboard/other hooks) — use the in-app path (double Home).
- Android drops a second Home press that arrives within milliseconds; the double-press window is 0.9 s; test with two `input` invocations.
- `FLAG_ACTIVITY_EXCLUDE_FROM_RECENTS` only applies when a task is CREATED; the raw `dumpsys activity recents` keeps the current top task even if excluded: judge Recents by the Recents screen/dump taken while Recents is open.
- killBackgroundProcesses did NOT close his apps on the tablet; Notification access does not exist on Android Go; injected keys bypass the accessibility key filter.
- Pressing Home right before starting Solitaire raced on the slow tablet (Solitaire ended up behind the home screen): never press Home in the reset.
- Emulator-only quirks: no nav bar in the layout, Calendar/Contacts tasks from earlier steps linger in Recents, Settings is a persistent process (cannot be "closed").
