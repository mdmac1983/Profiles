# Launcher design, feasibility and safety plan (2026-11-02)

Source of truth for *how* the custom launcher is built. Requirements: TASKS.md L1-L11. Screenshots: `research/uploads/2026-11-02/`
(1-3: Settings + Home settings, 4: home screen + long-press popup, 5: quick settings (only Auto-rotate), 6: panel, 7: stock app drawer).

## 1. The device (from Tj)
Alps 711 `tb8168p1_bsp`, MT8168B (4x Cortex-A53), Mali-G52 MC2, Android 10 Go (API 29), patch 2021-07-05, build `sys_mssi_t_32_ago` => **32-bit userspace
(armeabi-v7a)**, 600x1024 portrait tablet ("About tablet"), 3-button navigation, **96% storage used, 1.32 GB free**, locked bootloader, stock launcher
Quickstep v10. Consequences: no root, no system-signature, no custom ROM tricks; everything must work as a normal user APK plus adb-granted permissions.
Small, no native code (one APK, armeabi-v7a safe), no big caches (storage), low RAM.

## 2. What the stock launcher looks like (from the screenshots)
- Home: 3 columns x 4 rows of 600x1024, labels under icons, folders (Connect, Games), long-press empty space -> popup "Home settings / Wallpapers",
  wallpaper behind. Home settings: Notification dots, Add icon to Home screen, Allow Home screen rotation.
- App drawer: **translucent wallpaper background**, white rounded-square icon tiles, **5 columns**, "Search apps" bar on top (white), fast-scroll handle at right.
- That is AOSP Launcher3 (Go flavor + Quickstep), vendor-themed. Matching it exactly means *using its code and resources*, not redrawing it.

## 3. Decision: port AOSP Launcher3 (Go) android-10.0.0_r47, WITHOUT the Quickstep recents layer
- AOSP is reachable from this container and CI. Pin + fetch: `bash tools/fetch_launcher3.sh` (Launcher3 + SystemUI plugin API; 12 MB, Apache-2.0).
- **Quickstep proper cannot be an installable APK.** Its recents/gesture half (`quickstep/`, `sysui_shared`) talks to SystemUI through
  privileged/signature-only interfaces (OverviewProxyService, system-only permissions). It must be platform-signed and installed in /system.
  Not possible on a locked bootloader. The non-Quickstep Launcher3 (home, drawer, folders, search, widgets, wallpapers, icon grid) is the same code
  minus recents and builds as a normal APK (`l3goWithoutQuickstep` flavor in AOSP's own `build.gradle`).
- **Recents / overview** with 3-button nav is expected to keep working: SystemUI binds the recents component configured in the ROM
  (`config_recentsComponentName`), which is the stock Quickstep, independent of which app is the default Home. **VERIFY ON THE DEVICE (risk R3).**
- AOSP's Gradle build needs internal prebuilts that Google does not publish (`prebuilts/framework_intermediates`: `launcher_protos.jar`, `plugin_core.jar`,
  hidden-API framework). Plan: build `plugin_core` from the SystemUI plugin source (fetched), generate protos with the Gradle protobuf plugin from
  `protos/`, and replace the few @hide API uses with reflection/stubs (compile errors enumerate them). Pinned: AGP 8.13/Kotlin pins stay for our own code;
  the port module may need an older AGP: decide when the first compile runs. Gradle build and APK go through GitHub Actions.
- targetSdk **28** (AOSP's own Launcher3 value): on Android 10 only apps targeting <= 28 may call `WifiManager.setWifiEnabled` and `BluetoothAdapter.disable`,
  which the kill switch (L9) needs. Lint's Play-only target check is already disabled.

## 4. "Switching back to Quickstep" = pass-through mode (L8)
Our app is the default Home. Mode `QUICKSTEP` makes our Home activity forward every HOME intent straight to the stock launcher's explicit activity
(component found at runtime by querying HOME activities and excluding ourselves; never hard-coded) with a transparent theme, then finish. The gesture flips the
mode (and runs the "leaving custom" actions: unhide apps, IME -> SwiftKey, ...). The same gesture in Quickstep mode needs *our* surface: use an always-available entry
(our notification-free tile alternative / launcher shortcut / long-press power is not usable): candidates, decide with Tj: (a) a persistent "Launcher" app icon in
Quickstep's own drawer that flips the mode, (b) accessibility-service gesture (e.g. both volume keys long press) if he enables it.
The default-home setting is never changed by us (no permission for it, and nothing to break).

## 6. SAFETY ARCHITECTURE (L10): what the friend's launcher did wrong, and the rules that prevent it
Lock-screen glitch + all tiles returned = a launcher that (probably) held device-admin/keyguard/overlay power or rewrote secure settings on its own. Rules for this app:
1. **No device admin, no keyguard APIs, no `SYSTEM_ALERT_WINDOW`, no touching any `lockscreen.*` / `lock_*` setting, no screen-lock code path at all.** CI test greps the manifest and sources and fails the build if one appears.
2. **Every secure-setting write is opt-in, individually switched, default OFF, preceded by a saved snapshot of the previous value** (`RestoreStore`, persisted in device-protected storage so it survives lock state), only after `checkSelfPermission` succeeds, with a read-back verify and an automatic undo if the read-back differs.
3. **Restore everything** in one action: in-app button (also reachable in Quickstep mode via our icon), plus an adb script `tools/adb-restore.sh` that works even if our UI is dead (resets IME, tiles snapshot, hidden-app state, mode=QUICKSTEP, then `pm disable-user` of ourselves optional). Uninstall (`adb uninstall com.tj.launcher` or Settings > Apps) leaves Android with the stock launcher (our app does not own the default permanently: removing it makes Android fall back to Quickstep).
4. **Crash-loop breaker:** an uncaught-exception counter; 3 crashes in 2 minutes => mode=QUICKSTEP, all snapshots restored, feature switches off, a note shown next time. The launcher can never trap Tj in a crash loop.
5. **Boot safety:** the launcher does no work at boot except being a normal Home activity; no BOOT_COMPLETED receiver in the first releases; direct-boot unaware (cannot touch the lock screen). Android *Safe mode* (hold power -> long-press "Power off") disables all user apps and returns Quickstep: documented recovery.
6. **Staged releases** (Tj never installs an untested feature set):
   - v0.2 "safe core": ported launcher + pass-through gesture + crash breaker + Restore. NO secure settings, NO accessibility, NO notification access.
   - v0.3: L2, L3, L6 (pure in-app, no permissions).
   - v0.4+: L7, L5, L9, L4 one at a time, each default OFF and needing its own adb grant.
7. **Evidence before a release** (what "highly confident" means, honestly): (a) unit tests for every rule above; (b) an API 29 emulator run on GitHub Actions (KVM runners) that installs the APK, sets it as Home, exercises the drawer, hides apps, flips to Quickstep and back, forces crashes to trigger the breaker, runs Restore and asserts the settings are byte-identical to before; (c) screenshot comparison to Tj's screenshots; (d) a written pre-release checklist in TASKS.md; and (e) the first install on the real tablet is done with adb connected, with `tools/adb-restore.sh` ready. **I cannot test on the physical tablet, so I will state residual risk in every release note rather than claim certainty.**

## 7. Risks to verify on the tablet (R-list)
R1 vendor customisations of Quickstep (Alps theme/5-column drawer) differ from AOSP defaults: match via screenshots and grid config.
R2 `getHomeActivities` fallback / chooser dialog on first Home press: ensure we are set default in Settings > Apps > Default apps > Home app.
R3 recents button behaviour with a third-party Home (see section 3).
R4 32-bit only: no native libs in the port (Launcher3 has none).
R5 1.3 GB free: APK target < 15 MB, caches bounded.
R6 vendor Settings deep-link intents may not all exist: each curated entry resolves at runtime and hides if missing.
