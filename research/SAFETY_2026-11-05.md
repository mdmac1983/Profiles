# Safety audit, 2026-11-05 (AB1)

Tj, verbatim: *"It is important that this project doesn't break anything or require me to factory reset my tablet."* This audit overrides every other task (L10). It lists every way this app could hurt the tablet, what prevents it, what was found and fixed today, and how to get out of each situation **without a factory reset**.

## 1. Short answer

Nothing in the launcher can, by design, make the tablet need a factory reset. It is an ordinary user-space app: no root, no system-partition write, no device-admin policy, no `reboot` / `wipe` / `setprop` / credential call (searched in `app/src/main`, 2026-11-05: no match except two comments). It never reads or writes the lock-screen credential, and every window it puts on the lock screen is untouchable. Everything it changes outside its own storage is a short, known list of Android settings (section 3), each saved first and put back by **Launcher control > Restore everything**, by a one-line undo in the phone guide (section 10), or by Android's own Settings.

Today's audit found and fixed **three real problems** (section 4). None had hurt the tablet yet; one (the retail-demo flag) could have.

## 2. What would actually force a factory reset on Android, and where this app stands

| How a reset becomes necessary | This app |
| :- | :- |
| A boot loop from a change to the system partition or an unbootable system service | Not possible: the app writes nothing to `/system`; the system services it talks to are the ones apps may talk to. The Settings values it writes (section 3) are read at runtime by SystemUI, not by early boot code. |
| Locked out of the lock screen (the friend's launcher in L10) | No device admin, no `locksettings`, no credential access. Overlays over the lock screen: the number overlay, the wallpaper patch, the reset cover are `FLAG_NOT_TOUCHABLE`; the only touchable overlays are the power-menu card (only while Android's own power menu is open, removed when it closes, again by a 1.5 s re-check, and at service unbind / destroy / interrupt) and a 56 dp hotspot inside Solitaire (never on the lock screen). `onKeyEvent` returns `false` for every key: no key is ever swallowed. No wake lock, no `FLAG_SECURE` / `KEEP_SCREEN_ON` / `DISMISS_KEYGUARD`. |
| A "retail demo" user created at boot | **Fixed today** (section 4, problem 1). |
| A system app disabled that the system needs | Only `com.android.browser`, only if Tj chooses guide section 6 ("optional, reversible"); the helper's allow-list has the matching `BROWSER_ON`. |
| The wrong app force-stopped or its task removed | The helper re-checks a hard deny-list **inside the shell process**: system, providers, Google Play services, `com.mediatek.*`, Bluetooth, NFC, key chain, shell, permission controller, this app, the stock launcher and keyboards are refused whatever the app asks; at most 40 packages per line; task ids are re-resolved to a package by the helper from Android's own task list before anything is removed. |
| A crash loop in the home app | `CrashGuard`: three uncaught exceptions inside two minutes switch to Quickstep (the stock launcher), restore every saved setting, switch the keep-alive service off, and stay off until Tj clears it. |
| An accessibility list written wrongly | **Fixed today** (section 4, problem 2). |

## 3. Every setting the app changes (complete list, from the source)

| Setting | Written by | Saved first? | Put back by |
| :- | :- | :- | :- |
| `Settings.Secure sysui_qs_tiles` (quick-settings tiles) | `TileProfile`, on every mode switch and by the tile guard | yes (`RestoreStore.snapshotSecure`), and Tj's own Quickstep arrangement is remembered when he leaves Quickstep | Restore everything; guide undo `settings delete secure sysui_qs_tiles` (Android rebuilds its default list) |
| `Settings.Secure default_input_method` | `KeyboardSwitch` (only if Tj picked a different keyboard per mode) | yes | Restore everything |
| `Settings.Global policy_control` (status-bar hiding) | `ImmersiveProfile`, **default OFF** (opt-in) | yes (`snapshotGlobal`) | Restore everything; guide undo `settings delete global policy_control` |
| `Settings.Global window / transition / animator_duration_scale` | `AnimationSpeedup`, for the length of one return | the old values are kept in the app and put back after 10 s at the latest, on the next start of the app, and by Restore everything | automatic |
| `Settings.Secure enabled_accessibility_services`, `accessibility_enabled` | the helper's `A11YON` job (`adb-all`, "Do everything"), **merges** (never replaces) | merge keeps every other service | switch the helper off in Settings > Accessibility |
| `Settings.Global device_demo_mode` | **nobody any more** (retired); a one-time cleanup puts back a leftover | n/a | guide undo `settings put global device_demo_mode 0` |
| Permissions granted by `pm grant` (WRITE_SECURE_SETTINGS, DUMP, CHANGE_CONFIGURATION, READ_EXTERNAL_STORAGE, appops) | the guide, once | n/a | the launcher keeps working without them, those features switch off; `pm revoke` per card |
| Default Home app | Tj, in Android's Settings (FIRST_INSTALL.md) | n/a | Settings > Apps > Default apps > Home app > Quickstep |
| Compile state | guide `cmd package compile -m speed` | n/a | guide undo `cmd package compile --reset com.tj.launcher` |

The foreground service (`KeepAliveService`) holds no wake lock and does no work; it only keeps the process in memory. Restore everything and the crash breaker stop it.

## 4. Problems found and fixed today

1. **Retail-demo flag (`device_demo_mode`)**, used since v0.5 to remove the quick-settings pencil natively. AOSP's retail-mode code makes `RetailDemoModeService` create a demo user and switch to it when user 0 starts, i.e. at boot; nobody had tested a reboot with the flag on, and the way out of a surprise demo user can be a factory reset. **The whole feature was removed** (code, switch, guide card, tests); the accessibility cover over the pencil does the same job with no such risk. A leftover flag from the old option is put back to 0 once. Emulator proof: section `t`.
2. **Unquoted accessibility list.** The helper wrote `settings put secure enabled_accessibility_services <list>` through `sh -c` without quotes. A service with a nested class name (`pkg/pkg.Outer$Inner`, common) would have had `$Inner` expanded to nothing by the shell, silently disabling **another** accessibility service (for example TalkBack or switch access). The value is now single-quoted, restricted to the characters Android itself uses in component names, and refused (nothing written) otherwise. Unit tests: `ShellProtocolTest`.
3. **Shared app, Quickstep notification left behind** (AB3, not a crash risk but a privacy one): an app both launchers use kept its notification in the custom shade after the clean-up spared it. Such an app is now closed when it has a notification (section `pf`).

## 5. Recovering without a factory reset, in order of effort

1. **Inside the app**: Launcher control > Restore everything (turns every switch off, puts back every saved setting, stops the keep-alive service). Reach the control screen from the launcher icon.
2. **Back to the stock launcher**: the master failsafes work in the custom launcher (Konami volume/back code, five quick taps then a hold in the hidden Solitaire corner, the lock-screen handshakes). Or Android's Settings > Apps > Default apps > Home app > Quickstep.
3. **Crash loop**: nothing to do, `CrashGuard` does it.
4. **Accessibility helper misbehaving**: Settings > Accessibility > turn it off (every cover and the clean-up stop at once; nothing persists except the settings above).
5. **From the phone over OTG** (guide section 10, one card each): stop the helper, browser on, retail-demo flag off, `policy_control` delete, tile list delete, compile reset, permissions back.
6. **Safe mode** (Android's, third-party apps do not run, the stock launcher is Home, then Settings > Apps > uninstall / disable the launcher): hold Volume Down while the tablet boots (AOSP behaviour; **not tested on this tablet**), or long-press "Power off" in the stock menu. In the custom launcher our card sits over the stock menu, so use the boot method, or switch to Quickstep first.
7. **Uninstall the launcher** (Settings > Apps): the stock launcher is Home again; the saved Android settings are not undone by an uninstall, so use steps 1 or 5 first if a setting looks odd.

A reboot clears the shell helper (it is started again by one pasted line) and everything it was doing; the app does not start at boot by itself except as Home / the accessibility service.

## 6. Evidence, and what has NOT been proven

Unit tests (210 at this writing, 0 failures) cover every pure rule: the helper's deny-list and quoting, the task plan, tile / immersive / keep-alive policies, the crash breaker, the demo-flag cleanup. Emulator sections that exercise the safety paths: `t` (tiles guard, lock screen and a plain PIN work, demo flag stays off), `im` (policy_control follows the mode and is restored), `rt` and `pf` (clean-up closes only Quickstep's apps), `ka` (keep-alive), `b4`, `y2`, `b6` (covers), base / legacy (crash breaker, Restore).

**Not proven, and said plainly:** (a) behaviour on the real MT8168 across a reboot with every option on (the emulator cannot reproduce the MediaTek power menu or memory cleaner); (b) safe mode on this tablet; (c) that a future Android security patch does not change the system pieces the helper talks to (it fails closed: a refused call does nothing). The first thing to do after installing v0.7.0 is one reboot with the helper line pasted again and a look at Launcher control > status.
